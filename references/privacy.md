# 本人照片与授权

用户上传本人照片并要求制作头像，通常已授权完成这次编辑。不要重复询问已经明确的事项。只在服务商、用途、费用或照片传播范围发生实质变化且现有授权未覆盖时确认。

在首次发送给外部图像服务前，用一句话说明服务名称、要发送哪些照片和用途。不能确认该服务的数据保存或训练政策时，说“尚未核实”，不要承诺零保存、不会训练或绝对私密。要求核实政策时查服务商当时的官方条款。

不要公开原图、成品、含面部描述的任务记录或临时下载链接，不自动发到 LinkedIn。创建 Skill 仓库的授权不包括上传用户照片或代替用户发布头像。多人照先明确目标人物和编辑授权，不把其他人的脸作身份参考。

## 本地与 Git

- 原图、候选、输出与任务计划放在 `private/`、`inputs/`、`outputs/` 或 `runs/`；这些目录已忽略。
- 图片扩展名、`.env` 和 ZIP 也默认忽略；任务 JSON 若含面部描述、个人路径或私有链接，应放在已忽略目录。
- `.gitignore` 不能删除历史中已经提交的文件，私有仓库也不等于个人图片保险箱。提交前检查暂存内容，不用 `git add -f` 强行添加照片。
- 不将 base64 图片、EXIF 坐标、文件路径、密钥和私有签名 URL 写进 issue、提交信息或调试日志。示例只用虚构附件标签，不含真实人物信息。
- 对可导出的成品，用可用工具检查并清除不需要的 GPS/EXIF，再验证导出结果；本 Skill 和离线生成器不会自动完成元数据清理。没有工具时如实说明。

删除只覆盖本次创建的明确临时文件，依据用户要求或宿主临时文件策略执行；不宣称能够删除第三方服务保存的数据。不扫描用户电脑寻找照片、凭据或其他身份资料。

## 编辑边界

保留脸部结构、肤色、年龄特征和用户指定的身份表达。永久痣、疤痕、宗教服饰、眼镜、辅助设备等默认保留；是否修改由用户明确选择。临时瑕疵可轻微修饰，不能把磨皮或“美式审美”变成改变族裔外貌的理由。

不根据照片判断工作能力、性格、收入、学历或公司关系，不保证 offer、招聘通过率或官方证件审核。若用户转而请求护照、签证等照片，需要相应官方规格核验；此项目的职业头像预设不提供该类合规保证。
